## 2. 共享包（`packages/`）——主进程与测试的公共地基

| 包 | 职责 | 类比 |
|----|------|------|
| `@ns2-studio/pad-types` | 手柄报告（`PadReport`）、按键/方向/摇杆常量、中立报告 | 数据库表结构 |
| `@ns2-studio/protocol` | PC↔MCU 字节协议：7bit 打包、报告编码/解码、命令帧 | 网络协议栈 |
| `@ns2-studio/timeline-model` | 工程/录制文件 schema、校验、编译、烘焙 | 文档格式规范 |

三者都是**纯 TypeScript、零依赖 Electron**，可独立单测（`packages/*/test/`），被主进程的 electron-vite 配置内联打包（`electron.vite.config.ts` 的 `externalizeDepsPlugin.exclude`）。

## 5. 主进程组装（`main/index.ts`）

`app.whenReady()` 后按依赖顺序组装：

```
DeviceService（串口）
  → InputHub（包一层，成为唯一写入口）
    → Recorder（订阅 hub.reportSent，录制"实际发出去的"报告）
    → CaptureService（forward 源，读 Pro 手柄）
    → TimelineEngine（timeline 源，播放时 claim 输出源）
SettingsStore / ConfigStore / FileLogger（落盘）
AmiiboService（略）
registerIpc(...)（把所有服务绑定到 IPC + 事件转发到窗口）
createWindow()（preload 注入 window.api）
```

退出钩子：`before-quit` → `timeline.dispose()`、`capture.dispose()`、`device.shutdown()`（发中立报告 + 关串口）。

## 6. 核心数据流（四个场景）

| 场景 | 链路 | 输出源 |
|------|------|--------|
| 虚拟手柄 | UI → `pad:apply` → hub(manual) → writer → 串口 | `manual` |
| Pro 转发 | node-hid → parser → hub(forward) → writer → 串口 | `forward` |
| 时间轴播放 | 工程 → compile → engine 帧流 → hub(timeline) → writer | `timeline` |
| 录制 | 订阅 hub `reportSent` → 带 tUs 存帧 → nsrec JSON | 任意（不抢源） |

**唯一约束**：同一时刻只有一个输出源（InputHub 仲裁），切换必先中立（防卡键）。

## 7. 关键设计决策速览

1. **渲染进程永不碰硬件**：全部 I/O 在主进程，preload 白名单桥接。
2. **报告"只发最新"**：ReportWriter 合并同 tick 的重复报告，天然适配 250Hz 输入与时间轴帧流。
3. **延时交给硬件**：软件不模拟按键时长，而是持续下发状态帧；时长语义在固件/时间轴侧。
4. **纯函数可测**：三个 packages 与 recorder/parser/engine 的时钟/端口都注入（`TimelineClock`、`SerialPortLike`、`HidDeviceLike`、`RecorderClock`）。
5. **优雅降级**：node-hid 加载失败 → 采集不可用但不崩；串口丢失 → 引擎停、hub 回 idle。
6. **契约优先**：所有跨包类型变更先改 `docs/architecture/*`。
