## 1. 工具链全貌

### 1.1 ESP-IDF 是什么

ESP-IDF（Espressif IoT Development Framework）是乐鑫官方的嵌入式开发框架，**不是编译器，而是一整套体系**：

| 组成部分 | 作用 |
|----------|------|
| xtensa 交叉编译器（`xtensa-esp32s3-elf-gcc`） | 把 C 编译成 S3 芯片的机器码 |
| CMake + Ninja 构建系统 | 管理编译/链接/打包 |
| SDK 组件库 | `freertos`、`driver`（UART/GPIO）、`nvs_flash`、`tinyusb` 等 |
| `idf.py` 命令行工具 | 封装一切的入口 |
| `esptool.py` | 烧录工具（芯片 ROM 协议） |
| Kconfig 配置系统 | `sdkconfig` 菜单化配置（类似 Linux kernel） |

本项目锁定 **IDF 5.3.5**（`dependencies.lock:39`）。

### 1.2 依赖管理（组件注册表）

`main/idf_component.yml`：

```yaml
dependencies:
  espressif/esp_tinyusb: { version: "^2.0.0" }   # 从组件仓库拉取
  idf: { version: "^5.3" }
```

- `idf_component.yml` 声明**外部依赖**，首次构建时从 `components.espressif.com` 下载
- `dependencies.lock` 记录实际解析结果（`esp_tinyusb 2.1.1` → 底层 `tinyusb 0.19.0`），保证可复现构建
- 顶层 `CMakeLists.txt` 只有 4 行：引入 IDF 的 `project.cmake`，其余全部由 `main/CMakeLists.txt` 描述

```cmake
# main/CMakeLists.txt
idf_component_register(
    SRCS "main.c" "easycon/easycon.c" "hid/hid_device.c" "uart/uart_handler.c" "storage/storage.c"
    INCLUDE_DIRS "." "easycon" "hid" "uart" "storage"
    REQUIRES driver nvs_flash tinyusb      # 链接依赖的组件
)
```

## 2. 配置系统（sdkconfig）

### 2.1 配置来源与优先级

```
sdkconfig.defaults   ← 项目默认配置模板（提交到仓库）
sdkconfig            ← 构建时生成的当前配置（按需）
sdkconfig.n16r8      ← 已生成的 N16R8 具体配置（README 保证的版本）
```

编译时用 `-DSDKCONFIG=sdkconfig.n16r8` 指定；用 `idf.py menuconfig` 可以交互式改配置（等效于改 sdkconfig）。

### 2.2 关键配置项（`sdkconfig.defaults`）

| 配置 | 值 | 含义 |
|------|-----|------|
| `CONFIG_IDF_TARGET` | `"esp32s3"` | 目标芯片 |
| `CONFIG_ESP_CONSOLE_UART_NUM` | 1 | **日志走 UART1（GPIO17/18）**——所以正常烧录后电脑串口看不到日志 |
| `CONFIG_ESP_CONSOLE_UART_BAUDRATE` | 115200 | 日志波特率 |
| `CONFIG_ESP_SYSTEM_PANIC_SILENT_REBOOT` | y | 崩溃静默重启 |
| `CONFIG_TINYUSB_CDC_ENABLED` | y | 启用 CDC 类（当前被自定义描述符覆盖，见 01 文档第 4 节） |
| `CONFIG_TINYUSB_HID_COUNT` | 1 | HID 接口数量 |
| `CONFIG_FREERTOS_HZ` | 1000 | 系统节拍 1000Hz（固件所有毫秒计时依赖它） |

`sdkconfig.n16r8` 额外指定（N16R8 变体专属）：

```
CONFIG_ESPTOOLPY_FLASHSIZE_16MB=y          ← 烧录时按 16MB 处理
CONFIG_SPIRAM_TYPE_ESP32S3_OCTAL=y         ← 8MB Octal PSRAM
CONFIG_SPIRAM_SIZE=8388608
CONFIG_PARTITION_TABLE_CUSTOM=y            ← 自定义分区表
CONFIG_PARTITION_TABLE_CUSTOM_FILENAME="partitions_16mb.csv"
```

> **为什么有三种固件**：Flash 容量不同 → 分区表不同（8MB 版应用区 4MB、16MB 版应用区 6MB）→ 必须分开编译。当前仓库只提交了 `sdkconfig.n16r8`，另两个变体没有对应 sdkconfig 文件（release_bins 里三个 bin 字节数相同，推测实际只编了 N16R8）。

## 3. 分区表：芯片内部的"磁盘分区"

Flash 里的布局（`partitions.csv`，8MB 版；16MB 版见 `partitions_16mb.csv`）：

| 分区名 | 类型 | 偏移 | 大小 | 内容 |
|--------|------|------|------|------|
| nvs | data/nvs | 0x9000 | 24KB | 系统 NVS（WiFi 校准等） |
| phy_init | data/phy | 0xf000 | 4KB | 射频参数 |
| factory | app/factory | 0x10000 | 4MB(8MB版)/6MB(16MB版) | **应用**（`main` 编译产物） |
| storage | data/nvs | 0x410000(8MB)/0x610000(16MB) | 剩余 | **脚本数据**（`storage.c` 的 NVS 存这里） |

- 偏移/大小用十六进制写在 CSV 里，编译时被嵌入 `partition-table.bin`
- **bootloader 在 0x1000、分区表在 0x8000**（ESP32-S3 约定，ROM 固定查找），应用从 0x10000 开始
- `storage` 分区与 `nvs` 分区**类型都是 nvs**，但独立分区、独立命名空间——固件打开的是 `"easycon"` 命名空间

## 4. 编译：完整命令与产物

### 4.1 标准编译流程

```powershell
# 1. 加载 IDF 环境（IDF_PATH 指向安装目录）
. D:\Espressif\tools\Microsoft.v5.3.5.PowerShell_profile.ps1   # 见 pack_bin.ps1

# 2. 指定目标芯片（首次）
idf.py set-target esp32s3

# 3. 选择配置并构建（输出到独立 build 目录，便于做多变体）
idf.py -B build_n16r8 -DSDKCONFIG=sdkconfig.n16r8 build
```

### 4.2 构建产物（在 `build_<变体>/` 下）

| 文件 | 内容 | 烧录地址 |
|------|------|----------|
| `bootloader/bootloader.bin` | 二级引导程序（上电后 ROM 加载它） | 0x1000 |
| `partition-table.bin` | 分区表 | 0x8000 |
| `EasyMCU_ESP32S3.bin` | **应用固件**（main 编译链接结果） | 0x10000 |
| `flash_args` | **烧录参数清单**（`esptool.py write_flash` 的完整参数） | — |
| `merged.bin` | 三者合并的单一镜像（`merge_bin` 产物） | 0x0 |
| `project_description.json` | 构建元数据（配置快照） | — |

编译的宏观过程：

```
main/*.c  ──xtensa-gcc──▶  .o 目标文件
                          ├─链接─▶ .elf（含符号表，可 gdb 调试）
                          └─esptool──▶ 应用 .bin（带镜像头，可加密/压缩）
```

## 5. `pack_bin.ps1` 逐段解读

```
流程（对 n8r2 / n8r8 / n16r8 三个变体重复）：
1. 加载 IDF PowerShell profile（D:\Espressif\tools\Microsoft.v5.3.5.PowerShell_profile.ps1）
2. 进入 build_<v> 目录
3. 读 flash_args，提取：
   --flash_mode dio / --flash_freq 80m / --flash_size 16MB
   以及每个"地址 文件"对
4. 调用：esptool.py --chip esp32s3 merge_bin -o merged.bin
   --flash_mode dio --flash_freq 80m --flash_size 16MB
   [地址 文件 ...]
5. 移动 merged.bin → release_bins/EasyMCU_ESP32S3_<v>.bin
```

**为什么合并后地址填 0x0**：`merge_bin` 把三个文件按各自地址**拼成一个完整镜像**（bootloader 在镜像内 0x1000 处、分区表 0x8000、应用 0x10000），烧录时从 Flash 开头整体写入即可。ESP Flash Download Tool 只需一个文件 + 起始地址 0x0。

> 对比：`idf.py flash` 是**按地址逐个写**（先 bootloader 后分区表再应用）；合并镜像是一次写完。两种方式结果等价。

## 6. 烧录

### 6.1 进入下载模式（关键！）

芯片上电时，ROM 引导程序检查 GPIO0（BOOT 键）：

```
按住 BOOT → 按一下 RST → 松开 BOOT
= GPIO0 保持低电平复位 → ROM 进入下载模式（不是从 Flash 启动）
```

### 6.2 三种烧录方式

| 方式 | 命令/操作 | 说明 |
|------|-----------|------|
| IDF | `idf.py -p COM3 flash` | 自动按 flash_args 分地址烧 3 个文件 |
| 合并镜像 | ESP Flash Download Tool：芯片=ESP32-S3，选 `release_bins/*.bin`，**地址 0x0**，选 COM，Start | README 推荐，无需安装 IDF |
| esptool | `esptool.py --chip esp32s3 write_flash 0x0 EasyMCU_ESP32S3_n16r8.bin` | 命令行方式 |

### 6.3 烧录协议原理（esptool 在干什么）

```
PC ──(USB转串口桥)──▶ 芯片 ROM（下载模式）
1. 同步握手（0xC0 0x00 等命令，建立通信）
2. 擦除/写入 Flash（按扇区，带校验和）
3. 重启芯片（RST 命令）→ 从 Flash 正常启动
```

下载模式下 UART0 同时承担"串口"与"烧录"角色——这就是为什么 `com` 口既能烧录又能收发命令。

### 6.4 烧录后为什么电脑串口看不到日志

`sdkconfig.defaults` 把控制台日志指向 **UART1（GPIO17/18）**，而 UART0 完全被协议占用。想调日志：按 README 用 CH341A 接 GPIO17(TX)/GPIO18(RX)，115200 8N1。启动时 ROM bootloader 的短日志会短暂出现在 UART0（ROM 串口固定在 UART0），但应用起来后日志就切到 UART1 了。

## 7. 常见问题排查（编译/烧录）

| 现象 | 原因 | 处理 |
|------|------|------|
| `Could not find flash mode` / merge 报错 | `flash_args` 缺失或格式异常 | 确认 `build_<v>` 是完整构建产物；重新 `idf.py build` |
| 烧录失败 `A fatal error occurred: Failed to connect` | 没进下载模式 / 串口被占用 | 重按 BOOT+RST；关闭占用 COM 的软件（含 EasyCon） |
| 烧录成功但手柄不被识别 | 用了 8MB 变体固件烧到 16MB 板（分区表越界） | 按板型选对应 bin；确认 Flash 容量 |
| 编译报 `idf_component.yml` 拉取失败 | 无网络 / 组件缓存损坏 | `idf.py clean` + 删除 `managed_components` 重试 |
| 用错目标芯片 | `set-target` 未执行 | `idf.py set-target esp32s3` |
| 8MB 板用 16MB 分区表 | 分区表与 Flash 不匹配 | 用 `partitions_8mb.csv` 对应的 sdkconfig 重新编译 |

## 8. 与 ns2-studio 的关联

- **S0 冒烟工单**的"PC→S3→NS2"链路就是本文的烧录流程 + EasyCon 命令 `HELLO` 验证
- **本地环境**：当前机器无 IDF（`pack_bin.ps1` 引用的 `D:\Espressif\...` 不一定存在）——要自己编译需先安装 IDF 5.3；只想跑通链路则直接烧 `release_bins/EasyMCU_ESP32S3_n16r8.bin`
- ns2-studio 的固件方案（S0b）大概率 fork 本仓库改 `main/` 源码，编译/烧录管线可直接沿用：`build_<变体>` + `pack_bin.ps1` 的思路值得保留
